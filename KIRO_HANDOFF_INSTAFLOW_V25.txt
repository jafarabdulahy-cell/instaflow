============================================================
1) هدف پروژه
============================================================
InstaFlow / Shanisgram یک پنل اتوماسیون رسمی Instagram DM است که هدف آن شبیه ابزارهای حرفه‌ای مثل دایرکتم است:

- دریافت دایرکت اینستاگرام از مسیر رسمی Meta Graph API
- تبدیل دایرکت به لید/مخاطب CRM
- تعریف قوانین پاسخ خودکار توسط کاربر
- پاسخ به کلمات کلیدی مثل «منو»، «آدرس»، «رزرو»، «ساعت کاری»
- اتصال پاسخ‌ها به پیوست، قالب آماده، کارت فروشگاهی و لینک خارجی
- آماده‌سازی ساختار کامنت هوشمند: جواب داخل کامنت + ارسال دایرکت به کامنت‌گذار
- آماده‌سازی برای Webhook رسمی بعد از Publish/App Review/Business Verification Meta

فعلاً Appearance اولویت اصلی نیست، ولی UI باید موبایل‌فرست و قابل تست باشد.

============================================================
2) وضعیت اتصال Meta که قبلاً تست شده
============================================================
اکانت پایلوت:
- Page ID: 812762118592536
- Instagram Business ID: 17841453193519327
- Username: shanshin.rest

مسیر درست خواندن دایرکت:
- graph.facebook.com/{PAGE_ID}/conversations?platform=instagram

مسیر اشتباه که دیگر نباید مبنا باشد:
- graph.instagram.com/{IG_ID}/conversations

تست‌های انجام‌شده:
- /me/accounts جواب داده و Page شانشین را با instagram_business_account نشان داده است.
- conversations با limit=1 جواب داده است.
- messages برای conversation تستی جواب داده است.
- پیام‌های nazanin73.76 خوانده شده است.
- ارسال دستی/تستی DM از سمت API در نسخه‌های قبلی کار کرده است.

متغیرهای Railway/Env لازم:
- META_PAGE_ID=812762118592536
- META_PAGE_ACCESS_TOKEN=Page Access Token که با EAA شروع می‌شود
- INSTAGRAM_ID=17841453193519327
- INSTAGRAM_USERNAME=shanshin.rest
- META_WEBHOOK_VERIFY_TOKEN=shanshin_meta_webhook_2026
- INSTAFLOW_AUTO_REPLY_MODE=live
- INSTAFLOW_ALLOW_LIVE_SEND=true

نکته مهم:
Webhook endpoint تست Verify را پاس کرده است:
/api/meta/webhook?hub.mode=subscribe&hub.verify_token=shanshin_meta_webhook_2026&hub.challenge=12345
باید خروجی 12345 بدهد.

اما چون اپ Meta فعلاً Published نیست و Business Verification/App Review کامل نیست، Webhook واقعی برای دریافت پیام هنگام بسته بودن برنامه قابل اتکا نیست. فعلاً تست Auto Reply با باز بودن برنامه/InBox انجام می‌شود. بعد از Publish/App Review، همین منطق باید از Webhook واقعی اجرا شود.

6) دیتابیس
============================================================
Prisma schema شامل جدول‌های پایه است:
- Workspace
- User
- InstagramAccount
- Contact
- Conversation
- Message
- WebhookEvent

جدول‌های جدید اتوماسیون به صورت safe raw SQL با CREATE TABLE IF NOT EXISTS ساخته می‌شوند و در Prisma schema مدل نشده‌اند تا migration سنگین نیاز نباشد:
- instaflow_auto_reply_rules
- instaflow_media_assets
- instaflow_reply_templates
- instaflow_comment_rules
- instaflow_direct_cards

هشدار مهم:
در package.json دستور start عمداً prisma db push ندارد.
دلیل: در نسخه قبلی باعث خطای Data Loss شد و Prisma می‌خواست جدول‌های خام را حذف کند.
Start باید فقط این باشد:
- next start -H 0.0.0.0 -p ${PORT:-3000}

برای ساخت جدول‌های پایه فقط در مرحله setup یا دستی اجرا شود:
- npm run db:push

جدول‌های raw اتوماسیون با اولین استفاده خودشان ساخته می‌شوند.

7) نصب و اجرا برای Kiro / Local
============================================================
1. فایل ZIP را Extract کن.
2. وارد پوشه پروژه شو.
3. .env.example را به .env.local کپی کن.
4. DATABASE_URL و توکن‌های Meta را تنظیم کن.
5. نصب:
   npm install
6. ساخت Prisma Client:
   npx prisma generate
7. اگر دیتابیس تازه است:
   npx prisma db push
8. اجرا در توسعه:
   npm run dev
9. باز کردن:
   http://localhost:3000

Login اولیه:
- اگر دیتابیس هیچ user نداشته باشد، اولین ورود می‌تواند user اولیه بسازد.
- ایمیل پیشنهادی: admin@instaflow.local
- رمز پیشنهادی: 123456
- برای محیط production حتماً بعداً تغییر کند.

10) محدودیت‌های فعلی و ادامه کار
============================================================
- Webhook endpoint درست Verify می‌شود ولی برای دریافت رویداد واقعی بدون باز بودن برنامه، اپ Meta باید Published باشد.

- فعلاً برای تست، برنامه/Inbox باز می‌ماند.
- در آینده بعد از App Review، باید polling حذف و Webhook واقعی فعال شود.
- Upload مستقیم فایل داخل برنامه هنوز کامل نشده؛ فعلاً لینک عمومی ذخیره می‌شود.
- ارسال Native Card بسته به محدودیت API باید تست شود. fallback متن + لینک همیشه باید باقی بماند.
